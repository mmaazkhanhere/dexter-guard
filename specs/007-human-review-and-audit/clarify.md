# Spec 007 Clarifications

**Method:** Requirements clarification completed from the authoritative constitution and established contracts before technical planning. This is not an implementation decision record.

| Question | Resolution | Basis / impact |
| --- | --- | --- |
| Can a human adjudication clear a critical contradiction? | No. A critical finding requires correction and a subsequent valid full-note verification that no longer produces the blocker. | Constitution II; FR-23; prevents a rationale from overriding evidence integrity. |
| What makes a finding stale? | A finding is stale for approval when tied to any predecessor note revision. It remains in history. | Specs 002–006 immutable revision/run semantics; FR-19, FR-25. |
| May a successful claim-level run authorize approval? | No. It is feedback only. A final full-note verification of the latest complete revision is mandatory. | FR-21, FR-22. |
| Does unsupported evidence mean contradiction? | No. `UNSUPPORTED` is visibly distinct from `CONTRADICTED`; absent/invalid evidence is not highlighted as conflict. | Constitution I; Spec 004 finding invariants; FR-17. |
| What happens when a verification component fails? | Persist/retain the failed upstream run, create a critical operational review finding, and block approval. | Constitution II/VII; FR-22–FR-24. |
| Can the reviewer reject when verification fails? | Yes, with reviewer label and non-blank reason. | FR-24; rejection is a human disposition, not an approval assertion. |
| How is concurrent review editing handled? | `expectedRevision` compare-and-append; stale writers receive `409 STALE_REVISION`; no merge or overwrite. | Spec 001 versioning; FR-19. |
| Are upstream severity labels authoritative? | No. Spec 007 maps upstream facts/rules/statuses via deterministic `REVIEW_SEVERITY-v1`. | Constitution VII; FR-15. |
| How are the actual Spec 006 severity-policy keys mapped? | Spec 006’s current keys are preserved: `MEASUREMENT_OMISSION` → `CRITICAL`; `SYMPTOM_OMISSION`, `MOBILITY_ASSISTANCE_OMISSION`, `CARE_ACTION_OMISSION`, and `UNCERTAINTY_OMISSION` → `MAJOR`. Absent/unknown keys map conservatively to `MAJOR` for `MISSING`, `DISTORTED`, or `UNCERTAIN`; Spec 007 labels are never sent back to Spec 006. | FR-15; aligns the consumer with `COVERAGE_EXPECTATION-v1` without moving final severity ownership from Spec 007. |
| Can a Spec 006 suggestion be accepted directly? | No. Under CL-014 it remains a display-only source-derived aid. Spec 007 may accept only a separately validated `SuggestedCorrection` with a target note span, replacement, and source support. | FR-20; prevents an unstructured suggestion string from becoming an edit. |
| Can unresolved source items be approved after acknowledgement/adjudication? | No. Any successful coverage run with an unresolved source item remains approval-blocking, regardless of runtime completeness or non-critical finding decisions. | Spec 006 CL-010 and CL-015; FR-23. |
| Which component supplies Spec 005 source facts and explicit alignments? | A narrow Spec 005-owned `DeterministicValidationPort.run_for_revision` adapter resolves only immutable source facts and preselected alignments from Spec 005 repositories, then invokes its existing service. Spec 007 supplies source/note/revision references and never creates semantic alignments. | FR-22; preserves ADR 004's boundary. |
| How is claim extraction invoked by review? | The local PoC uses an injected in-process `ClaimExtractionPort.extract(noteRevisionId)`. It is not a new public HTTP endpoint. | FR-21, FR-22; avoids inventing a route. |
| How are SQLite review tables initialized? | The review repository uses idempotent `CREATE TABLE IF NOT EXISTS` schema initialization within the established local SQLite repository convention. No migration framework or dependency is introduced. | FR-25; maintains PoC scope. |
| Can a valid `EMPTY` Spec 003 extraction result lead to approval? | No. It creates an `INVALID` full-note verification with `EMPTY_CLAIM_SET_REQUIRES_REVIEW` and blocks approval. A future change requires a versioned specification update and acceptance fixture. | FR-22, FR-23; absence of extracted claims is not proof of fidelity. |
| Does this feature change sources, upstream findings, or medical records? | No. It appends review artifacts and successor note revisions only. | Constitution I–IV, VI; scope boundary. |
