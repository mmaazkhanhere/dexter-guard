# Requirements Quality Checklist

Evidence must be linked before any item is checked.

- [ ] Requirement completeness: FR-34–FR-49 are present, mandatory, and have owners.
- [ ] User-story coverage: Documentation, Verification, Review, and Evaluation journeys map to requirements.
- [ ] Acceptance testability: each scenario defines observable success/failure behavior.
- [ ] Backend compatibility: existing 001–008 contracts/routes are referenced; proposed routes are labelled.
- [ ] Evidence integrity: immutable source versions, code-point spans, derived quotations, and unavailable evidence behavior are specified.
- [ ] Revision consistency: expected revision, stale conflict, successor history, and stale async-response guards are specified.
- [ ] Critical approval blocking: server eligibility/full-note checks and failure behavior are specified.
- [ ] Frontend errors: validation, conflict, unavailable, timeout, invalid response, and persistence failures are specified.
- [ ] Evaluation integration: all required metrics, comparisons, saved/live labels, and case inspection use Spec 008 outputs.
- [ ] Deployment feasibility: composition root, Services gate, routing, PostgreSQL, duration, health, rollback, and secrets are specified.
- [ ] Security and privacy: synthetic-only scope and no browser credentials/secret telemetry are specified.
- [ ] Constitution: all seven principles and quality gates are addressed in plan.md.
- [ ] Out-of-scope protection: exclusions have not become requirements/tasks.
